성북 세이프패스 — 전체 구성도

관광객이 QR을 찍으면 화면이 열리고, 서버가 날씨·관광지·문서를 모아 보여 줍니다. 읽는 방향은 왼쪽에서 오른쪽이며, 화살표는 요청이 가는 방향입니다.

ONE LINE

한 줄로

QR → 웹 화면 → 서버 → (공공 API · AI · 자료 · 문서). 화면은 서버에만 말을 걸고, 외부와 직접 통신하지 않습니다.

KEYS

키는 서버만

API 키는 .env 에만 있고 화면과 코드에는 없습니다. 깃허브에도 올리지 않습니다.

STATUS

지금과 예정

내 컴퓨터에서 실행해 확인했습니다. 인터넷 공개(Vercel)는 예정입니다.

SYSTEM DESIGN · 2/3 ASK FLOW

질문하기 — 문서에서만 답하는 흐름

질문을 이해하고, 문서에서 찾은 내용 안에서만 답하며, 근거 문서 이름을 붙입니다. 화살표는 처리 순서이고, 파란 화살표는 AI에게 보내는 호출입니다.

RULE

문서에 없으면 모른다고

근거를 찾지 못하면 지어내지 않고 「자료 없음 + 1330 · 120」을 질문한 언어로 안내합니다.

AI ORDER

AI 순서

Claude → Groq → Gemini. 한 AI가 실패하면 다음으로 넘어가고, 답한 AI 이름을 남깁니다. 모두 실패하면 「지금은 AI를 쓸 수 없음」을 알립니다.

BY SCREEN

화면이 직접 보여 주는 것

날씨 · 미세먼지 · 이번 주 행사 · 가까운 관광지 · 쓰레기 배출은 AI가 아니라 화면 메뉴가 원래 데이터를 보여 줍니다.

SYSTEM DESIGN · 3/3 DATA & DEPLOY

자료 수집과 배포

실시간으로 받는 것과 미리 받아 두는 것을 나누고, 인터넷 공개까지의 예정 경로를 점선으로 표시했습니다. 이 쪽의 화살표는 자료가 흘러가는 방향입니다.

DATA

실시간과 미리 받기

날씨 · 미세먼지 · 이번 주 행사는 실시간(캐시), 관광지 · 먹거리 · 생활 안내는 미리 받아 data 폴더에 둡니다.

REVIEW

사람 확인

AI가 번역한 설명은 화면에 「확인 전」으로 표시하며, 팀이 확인한 뒤 확정합니다.

DEPLOY

깃허브 완료, Vercel 예정

깃허브(공개)에는 올렸고, 인터넷 주소를 만드는 Vercel 연결은 예정입니다. .env 와 키 값은 올리지 않습니다.
